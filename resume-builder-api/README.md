# resume-builder-api

NestJS API for the Resume Builder SaaS.

---

## Prerequisites

| Tool       | Version | Notes                                              |
| ---------- | ------- | -------------------------------------------------- |
| Node.js    | ≥ 18    | LTS recommended (20.x)                             |
| npm        | ≥ 9     | Ships with Node 18+                                |
| PostgreSQL | ≥ 14    | Or use Supabase / Neon / Render Postgres            |
| Redis      | —       | Upstash (serverless) or local Redis for OTP/session |
| Docker     | ≥ 24    | Only for Docker / Render deployments                |

---

## Monorepo Build Chain

The API depends on three internal packages that **must be built first** (in order):

```
resume-builder-shared → packages/resume-schemas → packages/resume-intelligence → resume-builder-api
```

The `prebuild` and `prestart:dev` scripts handle this automatically.

## 1. Development Environment (Local)

### 1.1 Install dependencies

```bash
# From monorepo root
cd resume-builder-shared && npm install && cd ..
cd packages/resume-schemas && npm install && cd ../..
cd packages/resume-intelligence && npm install && cd ../..
cd resume-builder-api && npm install
```

### 1.2 Configure environment

```bash
cd resume-builder-api
cp .env.example .env
```

Edit `.env` with your values:

```env
# ── Core ──
PORT=4001
NODE_ENV=development
CORS_ORIGIN=http://localhost:4000

# ── Database ──
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/resume_builder?schema=public

# ── Auth ──
JWT_SECRET=dev-secret-change-me
JWT_EXPIRES_IN=7d
JWT_REFRESH_SECRET=dev-refresh-secret-change-me
JWT_REFRESH_EXPIRES_IN=30d

# ── AI (Groq free tier) ──
AI_PROVIDER=groq
GROQ_API_KEY=gsk_your_key_here
GROQ_MODEL=llama-3.3-70b-versatile

# ── SMTP (Gmail example) ──
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=you@gmail.com
SMTP_PASS=your-app-password
SMTP_FROM=ATS Resume Builder <you@gmail.com>
SMTP_SECURE=false

# ── Stripe (test mode) ──
STRIPE_SECRET_KEY=sk_test_xxx
STRIPE_WEBHOOK_SECRET=whsec_xxx
STRIPE_PRICE_STUDENT=price_xxx
STRIPE_PRICE_PRO=price_xxx
STRIPE_SUCCESS_URL=http://localhost:4000/dashboard
STRIPE_CANCEL_URL=http://localhost:4000/dashboard
```

### 1.3 Set up database

```bash
# Generate Prisma client
npx prisma generate

# Run migrations (creates tables)
npx prisma migrate dev

# (Optional) Open Prisma Studio to inspect data
npx prisma studio
```

### 1.4 Start the API

```bash
npm run start:dev
```

API runs at `http://localhost:4001`. The `prestart:dev` script auto-builds shared packages.

### 1.5 Verify

```bash
curl http://localhost:4001/health
# → {"status":"ok"}

curl http://localhost:4001/health/db
# → {"status":"ok","database":"connected"}
```

## 2. Staging Environment

Staging mirrors production but uses test/sandbox credentials.

### 2.1 Infrastructure

| Service    | Recommended                       |
| ---------- | --------------------------------- |
| Hosting    | Render (Starter plan, $7/mo)      |
| Database   | Supabase free tier or Render PG   |
| Redis      | Upstash free tier                 |
| Stripe     | Test mode (`sk_test_` keys)       |
| AI         | Groq free tier                    |
| SMTP       | Gmail App Password or SendGrid    |

### 2.2 Environment variables

Set these in the Render dashboard (or your staging host):

```env
NODE_ENV=production
PORT=4001
CORS_ORIGIN=https://ats-rb-web-staging.onrender.com

DIRECT_URL=postgresql://user:pass@host:5432/postgres?schema=public

# Auth — auto-generated on Render via render.yaml
JWT_SECRET=<auto-generated>
JWT_REFRESH_SECRET=<auto-generated>
JWT_EXPIRES_IN=7d
JWT_REFRESH_EXPIRES_IN=30d
TOKEN_ENC_KEY=<64-hex-char-key>

# Redis
REDIS_URL=https://xxx.upstash.io
REDIS_TOKEN=xxx

# AI
AI_PROVIDER=groq
GROQ_API_KEY=gsk_xxx
GROQ_MODEL=llama-3.3-70b-versatile
AI_TIMEOUT_MS=30000
AI_FREE_MAX_REQUESTS_PER_DAY=10

# SMTP

SMTP_FROM=ATS Resume Builder <staging@example.com>

# Stripe (TEST mode)

STRIPE_WEBHOOK_SECRET=whsec_xxx
STRIPE_PRICE_STUDENT=price_test_student
STRIPE_PRICE_PRO=price_test_pro
STRIPE_SUCCESS_URL=https://ats-rb-web-staging.onrender.com/dashboard

# India pricing (optional, test mode)
```

### 2.3 Deploy

Use the Render Blueprint (`render.yaml` at repo root) — see [Production > Docker / Render](#34-docker--render-deployment) below. Change the `branch` field to your staging branch.

### 2.4 Run migrations on staging

```bash

npx prisma migrate deploy
```

## 3. Production Environment

### 3.1 Bare-metal / VM deployment

```bash
git clone <repo>
cd ats-resume-builder

# Build shared packages in order
cd resume-builder-shared && npm ci && npm run build && cd ..
cd packages/resume-schemas && npm ci && npm run build && cd ../..
cd packages/resume-intelligence && npm ci && npm run build && cd ../..

# Install and build API
cd resume-builder-api
npm ci
npx prisma generate
npx prisma migrate deploy    # Run migrations (no prompts)
npm run build

# Start
NODE_ENV=production node dist/main.js
```

### 3.2 Environment variables (production)

Same as staging but with **live** credentials:

```env
NODE_ENV=production
PORT=4001
CORS_ORIGIN=https://your-domain.com

DATABASE_URL=postgresql://user:pass@host:6543/postgres?schema=public&sslmode=require&connection_limit=10
DIRECT_URL=postgresql://user:pass@host:5432/postgres?schema=public&sslmode=require

JWT_SECRET=<strong-random-64-char>
JWT_REFRESH_SECRET=<strong-random-64-char>
TOKEN_ENC_KEY=<64-hex-char-key>

STRIPE_SECRET_KEY=sk_live_xxx            # ← LIVE key
STRIPE_WEBHOOK_SECRET=whsec_live_xxx
STRIPE_PRICE_STUDENT=price_live_student
STRIPE_PRICE_PRO=price_live_pro
STRIPE_PRICE_STUDENT_INR=price_live_student_inr
STRIPE_PRICE_PRO_INR=price_live_pro_inr
STRIPE_SUCCESS_URL=https://your-domain.com/dashboard
STRIPE_CANCEL_URL=https://your-domain.com/dashboard

# Social Login (production redirect URIs)
GOOGLE_LOGIN_REDIRECT_URI=https://api.your-domain.com/auth/social/google/callback
LINKEDIN_REDIRECT_URI=https://api.your-domain.com/auth/social/linkedin/callback
SOCIAL_LOGIN_SUCCESS_URL=https://your-domain.com/auth/callback

FORCE_DISABLE_RATE_LIMIT=false
```

### 3.3 Process manager (PM2)

```bash
npm install -g pm2

# Start
pm2 start dist/main.js --name ats-api -i max

# Auto-restart on reboot
pm2 startup
pm2 save

# Monitor
pm2 monit
```

### 3.4 Docker / Render deployment

Build and run the API Docker image locally:

```bash
# From monorepo root
docker build -t ats-api -f Dockerfile .
docker run -p 4001:4001 --env-file resume-builder-api/.env ats-api
```

**Deploy to Render via Blueprint:**

1. Push `render.yaml` to your repo (already included at repo root)
2. Go to Render → **New** → **Blueprint** → connect your GitHub repo
3. Render auto-detects `render.yaml` and creates the `ats-rb-api` service
4. Fill in env vars in the Render dashboard (variables with `sync: false`)
5. Deploy — Render builds the Docker image and starts the service
6. After first deploy, run migrations via Render Shell:
   ```bash
   npx prisma migrate deploy
   ```

## Database URL Format

- Use `postgresql://` or `postgres://` (not `prisma://`)
- For Supabase: use the **pooler** URL (port 6543) for `DATABASE_URL` and **direct** URL (port 5432) for `DIRECT_URL`
- Include SSL in production: `?sslmode=require&connection_limit=10&pool_timeout=30`

## Troubleshooting

| Issue                                  | Fix                                                                                    |
| -------------------------------------- | -------------------------------------------------------------------------------------- |
| `P2024` pool timeout                   | Reduce `PRISMA_CONNECTION_LIMIT`, check Supabase pooler settings                       |
| `nest` command not found               | Use `npx nest build` or ensure `@nestjs/cli` is in devDependencies                    |
| Prisma client not generated            | Run `npx prisma generate` before build                                                 |
| CORS errors from frontend              | Set `CORS_ORIGIN` to the exact frontend URL (including `https://`)                     |
| Port already in use                    | Kill existing process or change `PORT` in `.env`                                       |
| Shared package import errors           | Run `npm run build:deps` to rebuild shared packages                                    |
