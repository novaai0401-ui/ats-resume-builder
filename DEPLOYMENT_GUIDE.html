1 External Services (Set Up FIRST)

These must be ready before deploying either the API or the Web app.

1A. PostgreSQL Database — Supabase

  1. Go to supabase.com → New Project
  2. Choose region close to Render (Oregon = US West)
  3. Set a strong database password
  4. Go to Settings → Database
  5. Copy Connection string (URI) → DATABASE_URL
  6. Copy Direct connection string → DIRECT_URL
Format:
DATABASE_URL = postgresql://postgres:[PASS]@db.[REF].supabase.co:6543/postgres
DIRECT_URL = postgresql://postgres:[PASS]@db.[REF].supabase.co:5432/postgres

1B. Redis — Upstash

  1. Go to upstash.com → Create Database → region US West
  2. Copy UPSTASH_REDIS_REST_URL → REDIS_URL
  3. Copy UPSTASH_REDIS_REST_TOKEN → REDIS_TOKEN

1C. Stripe (Billing)

  1. Go to dashboard.stripe.com → Developers → API Keys
  2. Copy Secret Key → STRIPE_SECRET_KEY
  3. Create Webhook (after API deploy) → STRIPE_WEBHOOK_SECRET
  4. Create two Price objects → STRIPE_PRICE_STUDENT, STRIPE_PRICE_PRO

1D. OAuth Providers (Social Login)

GitHubgithub.com/settings/developers → OAuth AppsGITHUB_CLIENT_ID, GITHUB_CLIENT_SECRET

1E. SMTP — Gmail with App Password

  1. Enable 2FA on your Google account
  2. Go to myaccount.google.com/apppasswords → Generate password

1F. AI Service — Groq

  1. Go to console.groq.com → API Keys → Create key
  2. Copy → GROQ_API_KEY

# TOKEN_ENC_KEY (64 hex chars = 256-bit key)

3 Deploy Web on Render

3A. Create Render Web Service

With render.yaml committed to the repo, both services can be created at once via a Blueprint, or individually:

Option A — Blueprint (recommended, both services at once)

  1. Go to render.com → New → Blueprint
  2. Connect the repo: novaai0401-ui/ats-resume-builder
  3. Render auto-detects render.yaml and proposes ats-rb-api + ats-rb-web
  4. Click Apply and fill in the sync: false env vars in the dashboard

Option B — Manual (Web service only)

  1. Go to render.com → New → Web Service
  2. Connect the repo: novaai0401-ui/ats-resume-builder
  3. Configure:
    • Runtime: Docker
    • Dockerfile Path: ./Dockerfile.web
    • Docker Context: . (repo root)
    • Plan: Starter ($7/mo) — no cold starts
    • Region: Singapore (or closest to your users)
    • Health Check Path: /

3B. Set Environment Variables in Render Dashboard

Service page → Environment tab:

VariableValue
NODE_ENVproduction
PORT4000
NEXT_PUBLIC_API_URLhttps://ats-rb-api.onrender.com
NEXT_PUBLIC_SESSION_IDLE_TIMEOUT_MS1800000
NEXT_PUBLIC_ADMIN_EMAILSnovaai0401@gmail.com
Important: NEXT_PUBLIC_* values are baked into the Next.js bundle at build time. Any change requires a manual redeploy (Manual Deploy → Clear build cache & deploy).

3C. Deploy

Render builds the Docker image and deploys automatically on each push to main.

Note your Render Web URL (e.g. https://ats-rb-web.onrender.com)

5 Set Up GitHub Actions (CI/CD)

5A. Auto-Deploy (Default, No CI Needed)

By default, Render watches the main branch and rebuilds both services on every push. This is configured by render.yaml — no GitHub Actions setup is required.

5B. Optional — Deploy Hooks via GitHub Actions

If you want explicit CI-driven deploys (e.g. gated by tests), Render exposes a Deploy Hook URL per service:

  1. Render → service → Settings → Deploy Hook → copy the URL for each service
  2. Disable auto-deploy on the service if you want the workflow to be the only trigger
  3. Add GitHub Secrets (repo Settings → Secrets and variables → Actions):
Secret NameWhere to Get It
RENDER_API_DEPLOY_HOOKRender → ats-rb-api → Settings → Deploy Hook
RENDER_WEB_DEPLOY_HOOKRender → ats-rb-web → Settings → Deploy Hook

The workflow .github/workflows/deploy-render.yml posts to those hooks on every push to main.

5C. Create GitHub Environment

Repo Settings → Environments → New environment → name: production

Deployment Sequence — Summary

 PHASE 1 — External Services
  ① Supabase (PostgreSQL)         → DATABASE_URL, DIRECT_URL
  ② Upstash (Redis)               → REDIS_URL, REDIS_TOKEN
  ③ Groq (AI)                     → GROQ_API_KEY
  ④ Gmail App Password (SMTP)     → SMTP_* variables
  ⑤ Generate JWT + encryption secrets locally

 PHASE 2 — Deploy API (Render)
  ⑥ Create Render Web Service (Docker)
  ⑦ Set all environment variables
  ⑧ Wait for build + deploy
  ⑨ Run: prisma migrate deploy
  ⑩ Verify: GET /health → 200 OK
  ⑪ Note your API URL

 PHASE 3 — Deploy Web (Render)
  ⑫ Create Render Web Service (Docker, Dockerfile.web)
     — or use Blueprint to create API + Web together
  ⑬ Set NEXT_PUBLIC_API_URL = Render API URL
  ⑭ Deploy
  ⑮ Note your Render Web URL

 PHASE 4 — Cross-Link
  ⑯ Set CORS_ORIGIN on API → Render Web URL
  ⑰ Update OAuth redirect URIs → Render API URL
  ⑱ Update Stripe webhook → Render API URL
  ⑲ Update success/cancel URLs → Render Web URL

 PHASE 5 — CI/CD (Optional)
  ⑳ Render auto-deploys on push to main by default
  ㉑ For gated deploys: add RENDER_*_DEPLOY_HOOK GitHub Secrets
  ㉒ Create "production" environment

 PHASE 6 — Verify
  ㉒ Full end-to-end test: register → login → resume → PDF
Key Rule: External services FIRST → API SECOND → Web THIRD → Cross-link LAST.
